01개요 & 핵심 개념

herdr는 tmux/zellij 같은 터미널 워크스페이스 매니저(멀티플렉서)이면서, 그 안에서 돌아가는 AI 코딩 에이전트(Claude Code, Codex, Gemini 등)의 상태를 감지·관리하는 데 특화된 도구입니다. 실제 터미널 프로세스를 백그라운드 서버에서 계속 실행시키고, 그 위에 구조(워크스페이스·탭·패널)를 얹습니다.

마우스 네이티브라서 패널·탭·워크스페이스·에이전트를 클릭하고, 분할 경계를 드래그하고, 우클릭 메뉴를 쓰는 것만으로도 대부분 조작이 가능합니다. 키보드는 선택 사항입니다.

Session (세션)영구적인 herdr 서버 네임스페이스. herdr는 기본 세션에 붙습니다. 완전히 분리된 환경이 필요할 때만 이름 있는 세션을 씁니다.
Workspace (워크스페이스)최상위 프로젝트 컨테이너. 레포·작업·조사 하나당 하나. 내부 에이전트 상태가 사이드바에 합산되어 표시됩니다.
Tab (탭)워크스페이스 안의 레이아웃. agents, logs, server, review처럼 뷰를 나눌 때.
Pane (패널)실제 터미널. 오른쪽/아래로 분할, 이름 변경, CLI로 읽기·입력·닫기 가능. 클라이언트가 분리돼도 유지됩니다.
Agent (에이전트)패널 안에서 herdr가 인식한 프로세스. 포그라운드 프로세스, 화면 매니페스트, 통합(integration)으로 감지.
구조 요약: Session ⊃ Workspace ⊃ Tab ⊃ Pane (⊃ Agent). 우선 워크스페이스로 나누고, 패널·소켓·런타임 상태까지 완전히 분리해야 할 때만 세션을 나누세요.

02에이전트 상태

상태의미
blocked입력·승인·결정이 필요함 (승인/질문 UI를 인식)
working에이전트가 작업 중
done작업을 끝냈지만 아직 확인하지 않음
idle완료 또는 대기 중이며 이미 확인함
unknown에이전트는 있지만 상태를 확신할 수 없음 (성공을 의미하지 않음)

idle과 done은 둘 다 "입력 가능" 상태입니다. Done 배지는 클라이언트별로 따로 추적되므로, 한 클라이언트에서 봤다고 다른 클라이언트의 배지가 지워지지는 않습니다. CLI/API는 서버의 "확인됨" 상태를 따르며, pane focus/agent focus로 확인 처리됩니다(읽기만으로는 처리되지 않음).

03모드 & 클라이언트/서버

세 가지 모드

모드동작
Terminal mode키 입력을 포커스된 패널로 보냄 (기본 상태)

그 밖에 Copy mode(prefix+[)와 Resize mode(prefix+r)가 있습니다.

클라이언트와 서버

herdr는 기본적으로 백그라운드 서버 + 하나 이상의 클라이언트로 동작합니다. 서버가 패널과 프로세스를 소유하고, 클라이언트는 그 서버에 붙은 터미널 UI입니다.

  • 클라이언트가 하나면 모든 탭이 그 크기를 따름
  • 여러 클라이언트면 각자 다른 워크스페이스/탭을 볼 수 있고, 같은 탭을 보면 마지막으로 상호작용한 클라이언트가 크기를 결정
  • ctrl+b q 로 분리(detach) → 서버와 에이전트는 계속 실행
  • 세션 자체를 끝내려면 herdr server stop

04Prefix 개념

터미널 안의 프로그램들이 이미 대부분의 키 조합을 쓰고 있기 때문에(ctrl+c 중단, ctrl+r 히스토리 검색 등), herdr는 키 하나만 예약합니다. 기본 Prefix는 ctrl+b입니다.

prefix+c = ctrl+b를 누르고 떼었다가 c를 누름.
언제든 prefix+? 로 활성 단축키 전체를 볼 수 있고, 도움말 안에서 / 로 필터링(Backspace 편집, ctrl+u 지우기)합니다.

새 탭
prefix+c
오른쪽 / 아래 분할

패널 간 이동
prefix+h/j/k/l
워크스페이스 탐색
prefix+w
분리 (모두 계속 실행)
prefix+q

Navigate 모드 전용 키

navigate_workspace_*, navigate_pane_* 설정은 Navigate 모드 안에서만 동작하므로 j, k 같은 일반 키를 쓸 수 있습니다(예: navigate_workspace_down = "j", navigate_pane_down = "ctrl+j"). 왼쪽/오른쪽 화살표는 항상 패널 좌/우 이동의 별칭입니다.

마우스

  • 패널·탭·워크스페이스·에이전트 클릭으로 포커스
  • 분할 경계 드래그로 크기 조절, 우클릭 메뉴
  • 마우스 드래그로 선택하면 복사 모드 없이 바로 복사
  • 마우스 캡처 끄기: [ui] mouse_capture = false

07Goto 피커 (prefix+g)

모든 에이전트와 터미널을 워크스페이스별로 묶어 한 줄씩 보여줍니다. 분할된 탭의 패널도 각각 별도 행으로 나옵니다.

키동작
Enter / 클릭해당 위치로 바로 이동
/검색 (이름·에이전트 종류·탭·워크스페이스·브랜치·경로)
↑↓ 또는 jk행 이동 (검색 입력 중이 아닐 때)
←→이전/다음 워크스페이스 섹션의 첫 항목으로 (검색 중에는 커서 이동)
b w i dblocked / working / idle / done 에이전트만 필터
a전체 터미널 다시 보기
팁: 에이전트를 여러 개 돌릴 때 prefix+g → b 로 승인이 필요한(blocked) 에이전트만 골라 처리하면 효율적입니다.

08복사 모드 (prefix+[)

분류키
이동hjkl, 단어 wbe, 큰 단어 WBE, 문단 {}
페이지PageUp/PageDown, ctrl+b/ctrl+f, 반 페이지 ctrl+u/ctrl+d
검색/ 정방향, ? 역방향, n/N 반복 (대문자 포함 시 대소문자 구분)
선택 시작v 또는 Space (V도 지원)
복사y 또는 Enter
나가기q 또는 Esc (Esc는 선택/검색을 먼저 해제)
기본 prefix가 ctrl+b이므로 복사 모드에서 ctrl+b는 페이지 업이 아니라 prefix 모드로 진입합니다. 복사 모드에서 ctrl+b 페이지 업을 쓰려면 prefix를 다른 키로 바꾸세요.
복사 모드 중에도 패널 프로세스는 멈추지 않고 출력이 계속 갱신됩니다.

10단축키 변경 / Prefix-free 설정

Prefix 바꾸기

[keys]
prefix = "ctrl+a"
# 여러 개도 가능 (첫 번째가 상태바에 표시되는 기본 prefix)
prefix = ["ctrl+space", "ctrl+s"]

Prefix 없이 바로 쓰는 단축키 추가

ctrl+alt 조합은 대부분의 터미널(Ghostty, iTerm2, kitty, WezTerm, Windows Terminal 등)과 OS에서 비어 있어 안전한 편입니다. 아래 설정은 prefix 바인딩을 유지하면서 직접 단축키를 덧붙입니다.

[keys]
focus_pane_left  = ["prefix+h", "ctrl+alt+h"]
focus_pane_down  = ["prefix+j", "ctrl+alt+j"]
focus_pane_up    = ["prefix+k", "ctrl+alt+k"]
focus_pane_right = ["prefix+l", "ctrl+alt+l"]
previous_tab     = ["prefix+p", "ctrl+alt+["]
next_tab         = ["prefix+n", "ctrl+alt+]"]
new_tab          = ["prefix+c", "ctrl+alt+c"]
split_vertical   = ["prefix+v", "ctrl+alt+d"]
split_horizontal = ["prefix+minus", "ctrl+alt+shift+d"]
zoom             = ["prefix+z", "ctrl+alt+z"]

tmux 스타일 원키 패널 크기 조절 (선택 액션)

[keys]
resize_pane_left  = "ctrl+shift+alt+left"
resize_pane_down  = "ctrl+shift+alt+down"
resize_pane_up    = "ctrl+shift+alt+up"
resize_pane_right = "ctrl+shift+alt+right"

피해야 할 ctrl+alt 조합

조합선점한 곳
ctrl+alt+방향키GNOME 워크스페이스 전환, Ghostty·Konsole 기본값
ctrl+alt+tUbuntu/Fedora "터미널 열기"
ctrl+alt+l / ctrl+alt+aKDE 화면 잠금 / attention window
ctrl+alt+s / ctrl+alt+uKonsole
ctrl+alt+f1..f12Linux 가상 콘솔 전환
macOS에서는 일반 alt 조합이 특수문자로 합성되는 경우가 많고, ctrl+j는 셸에서 Enter로 취급됩니다. 직접 단축키가 동작하지 않으면 터미널/OS가 먼저 가로챈 것이니 한쪽을 다시 바인딩하세요.
예전 커스텀 키를 버리고 새 기본값을 쓰려면 herdr config reset-keys (config.toml 백업 후 [keys] 제거).

11CLI · 실행 · 상태 · 업데이트

CLI는 실행 중인 서버와 로컬 소켓 API로 통신합니다. 대부분 명령은 스크립트 자동화를 위해 JSON으로 응답합니다.

herdr                         # 기본 세션 실행 또는 연결
herdr --session work          # 이름 있는 세션 사용
herdr --remote workbox        # SSH로 원격 연결 (로컬 키바인딩 사용)
herdr --remote workbox --remote-keybindings server  # 서버 쪽 키바인딩 사용
herdr --default-config        # 기본 설정 출력
herdr update                  # 설정된 채널에서 다운로드·설치
herdr channel show            # stable / preview 확인
herdr channel set preview     # 프리뷰 빌드 구독
herdr channel set stable      # 안정판으로 복귀
herdr --version               # 버전 출력

herdr status                  # 상태
herdr status server
herdr status client

herdr api schema              # 소켓 프로토콜 스키마 요약
herdr api schema --json       # 전체 JSON Schema
herdr api schema --output herdr-api.schema.json

실험적 라이브 핸드오프는 herdr --remote 또는 herdr update에 --handoff를 명시해야 합니다.

12저장된 SSH 머신

herdr machine list [--json]
herdr machine add workbox [--label "Build machine"] [--remote-session <n>]
herdr machine rename <profile-id> --label "New name"
herdr machine disable <profile-id>
herdr machine enable <profile-id>
herdr machine remove <profile-id>
herdr machine status [<label-or-id>] [--json]   # SSH·원격 herdr 점검
herdr machine reconnect <label-or-id>          # SSH 재인증/검증
  • machine add는 원격 설치 상태를 확인하고, 필요할 때만 승인 후 설치/업데이트한 뒤 세션 서버를 시작합니다.
  • 비밀번호·개인키 등 SSH 자격증명은 저장하지 않습니다.
  • 머신 제거/비활성화는 연결만 끊고 원격 세션은 계속 실행됩니다.

다른 머신으로 명령 보내기 (--machine 전역 prefix)

herdr --machine "Build machine" agent list
herdr --machine <profile-id> pane list
herdr --machine "Build machine" agent prompt w1:p1 "review this change"
herdr --machine "Build machine" worktree create --cwd /srv/project --branch review
UI에서 머신을 선택해도 CLI 대상은 바뀌지 않습니다. --machine은 --session/--remote와 함께 쓸 수 없고, 원격에서는 --current로 로컬 패널을 가리킬 수 없습니다. 지원 명령: workspace, worktree, tab, pane, notification, agent(attach 제외), api snapshot, status server, 일부 server/plugin 명령.

14서버

herdr server                          # 헤드리스 서버를 명시적으로 실행 (서비스용)
herdr server stop                     # 서버 종료 = 세션의 모든 패널 종료
herdr server reload-config            # 패널 재시작 없이 설정 반영
herdr server agent-manifests [--json] # 에이전트 감지 매니페스트 상태
herdr server update-agent-manifests [--json]  # 원격 매니페스트 즉시 업데이트
herdr server reload-agent-manifests   # 로컬 오버라이드 수정 후 리로드

표시용 메타데이터 (사이드바 토큰)

herdr pane report-metadata <pane_id> \

22에이전트

herdr agent list
herdr agent get <target>
herdr agent read <target> [--source visible|recent|recent-unwrapped|detection] [--lines N] [--format text|ansi] [--ansi]
herdr agent send-keys <target> <key> [key ...]
herdr agent prompt <target> <text> [--wait] [--until STATUS]... [--timeout MS]
herdr agent rename <target> <n>|--clear
herdr agent focus <target>
herdr agent wait <target> [--until STATUS]... [--timeout MS]
herdr agent attach <target> [--takeover]
herdr agent start <n> --kind KIND --pane ID [--timeout MS] [-- <agent-args...>]
herdr agent explain <target> [--json|--verbose]
herdr agent explain --file PATH --agent LABEL [--json|--verbose]

핵심 규칙

  • target = 고유한 에이전트 이름 또는 에이전트가 있는 패널 ID.
  • agent start: 셸이 포그라운드인 빈 패널에서 에이전트를 실행. 이름은 [a-z][a-z0-9_-]{0,31}. 기본 타임아웃 30000ms (3000 초과 ~ 300000 이하).
  • 지원 kind: pi claude codex gemini cursor devin agy cline omp mastracode opencode copilot kimi kiro droid amp grok hermes kilo qodercli qwen letta maki muse
  • agent prompt: 텍스트 + Enter를 한 번에 제출. 이미 blocked면 agent_blocked 반환. --wait 시 5초 안에 working/blocked가 관측되지 않으면 agent_prompt_stalled.
  • --until 기본값은 idle, done, blocked. --until은 --wait와 함께만 사용.
  • agent explain: 서버가 상태를 어떻게 판정했는지 설명 (이슈 리포트에 --json).
일반 터미널·서버·테스트·셸에는 pane send-text / send-keys / run과 terminal attach를, 코딩 에이전트에는 agent 명령을 쓰세요.

39자동화 레시피

① 프로젝트 워크스페이스 + 에이전트 2개 + 개발 서버 자동 구성

#!/usr/bin/env bash
set -e
WS=$(herdr workspace create --cwd ~/project --label api --no-focus)
WS_ID=$(echo "$WS"   | jq -r .result.workspace.workspace_id)
ROOT=$(echo "$WS"    | jq -r .result.root_pane.pane_id)

# 오른쪽 분할 → Claude, 아래 분할 → 개발 서버
RIGHT=$(herdr pane split "$ROOT" --direction right | jq -r .result.pane.pane_id)
DOWN=$(herdr pane split "$ROOT" --direction down --ratio 0.3 | jq -r .result.pane.pane_id)

herdr agent start reviewer --kind claude --pane "$RIGHT"
herdr agent start builder  --kind codex  --pane "$ROOT"

herdr pane run "$DOWN" "npm run dev"
herdr pane wait-output "$DOWN" --match "ready" --timeout 60000

herdr workspace focus "$WS_ID"
